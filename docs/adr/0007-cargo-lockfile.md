# ADR 0007: Lock collector dependencies and align Rust toolchains

- Status: accepted
- Date: 2026-11-25

## Context

The collector previously had no committed `Cargo.lock`. CI and the Docker builder could therefore resolve different transitive dependency versions, and later builds could drift without a source change. The Docker builder already used Rust 1.89, while CI followed the moving stable toolchain.

## Decision

- Commit the Cargo lockfile generated by the validated collector CI run.
- Copy `collector/Cargo.lock` into the Docker build stage and run the release build with `--locked`.
- Pin CI Rust installation to 1.89.0, matching the Docker builder's Rust 1.89 toolchain.
- Use Cargo's `--locked` mode for CI Clippy, tests, builds, and dependency-tree inspection. Security audit reads the same committed lockfile.
- Run the security-hardening job for the deployment-integration branch so the lockfile is audited before merge.
- Remove the temporary workflow artifact used only to transfer the generated lockfile.

## Consequences

CI, Docker, and dependency auditing now consume the same committed dependency graph and compiler release. A dependency update must intentionally update and review `Cargo.lock`; locked CI and image builds fail rather than silently resolving a different graph.

This improves dependency reproducibility but does not claim byte-for-byte reproducible container images: base-image digests, OS package snapshots, and production-environment evidence remain separate release-readiness concerns tracked in issue #24. No application protocol, persistence schema, or delivery semantics change.
