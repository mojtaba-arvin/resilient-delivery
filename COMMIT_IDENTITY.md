# Commit identity and attribution policy

For maintainer-directed AI-assisted implementation, use Git author `Mojtaba Arvin <m.arvin@live.com>` only after confirming this exact email is verified on the maintainer's GitHub account. Do not use model, assistant, AI-agent, Copilot, Claude, Cursor, Codex, Gemini, generic agent, or bot identities as the author. Do not add bot/AI `Co-authored-by` trailers.

Include `<!-- maintainer-directed-ai-work -->` in the PR body for owner-authorized AI-assisted work. This machine-readable marker requires at least one commit whose GitHub-resolved author is `mojtaba-arvin` and validates that account against the exact maintainer name/email. Other human contributor identities remain unchanged. Disclose AI assistance in the PR description; the marker does not claim the maintainer personally typed every line.

Preserve every real human contributor's original author name/email. Never relabel another person as the maintainer and never rewrite historical commits.

Genuine GitHub Actions/Dependabot commits are permitted only when all of the following hold: the PR has the explicit `allow-automation-commits` label; both the GitHub-resolved author and committer are the same allowlisted automation account; GitHub reports that account as a Bot; and both Git author/committer metadata fields are present. This exception is for commits actually generated by that automation, never agent-written implementation. The label is an explicit authorization signal, not proof of provenance; maintainers must verify the generating workflow or Dependabot activity. Bot co-author trailers remain prohibited.

A GitHub `web-flow` committer is distinct from the commit author. It is allowed for human-authored commits and must not cause the human author to be relabeled. Maintainer author and committer metadata are independently checked whenever GitHub resolves either identity to `mojtaba-arvin`.

Convenience defaults (not enforcement):

```sh
git config --global user.name "Mojtaba Arvin"
git config --global user.email "m.arvin@live.com"
```

`scripts/check_commit_identity.py` checks all PR commits, author and committer metadata, prohibited bot/agent identities, co-author trailers, the explicit automation exception, and the maintainer identity marker. The `Commit identity` workflow uses a read-only token, checks out only the trusted base-branch validator, and runs on `pull_request` so a newly introduced workflow is testable before merge. Configure this check as required in branch protection/rulesets where governance permits; a workflow alone does not block merges.

Git metadata is self-asserted: validation cannot prove who physically typed code or detect every disguised agent identity. Verify the email association and disclose AI assistance transparently.

Never amend, rebase, or cherry-pick a contributor's work under the maintainer identity. Preserve the contributor's original author fields and add a separate maintainer-authored commit for AI-assisted changes.
